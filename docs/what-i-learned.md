# 코딩 에이전트 구현 회고 요약 (Lessons Learned)

코딩 에이전트를 직접 설계·구현·개선하면서 얻은 핵심 엔지니어링 교훈을 빠르게 훑어볼 수 있도록 요약한 문서입니다.

> Runtime Topology·도구 호출·Context 관리·Subagent·Revert 동작 원리와 직접 구현 범위를 상세히 정리한 본문은 **[코딩 에이전트 구현 Review (`docs/coding-agent-study.md`)](coding-agent-study.md)**를 참고하세요.

---

## 1. 프롬프트 당부보다 물리적 실행 환경 분리가 먼저입니다

일반 챗봇과 달리 코딩 에이전트는 파일시스템·셸 프로세스와 직접 맞닿아 있어 문맥이 길어지면 프롬프트 제약을 어길 수 있습니다.

- 읽기 전용인 `Ask` 모드에서는 프롬프트 지시만 믿지 않고 아예 `execute` 도구가 빠진 읽기 전용 백엔드(`FilesystemBackend`)를 마운트해 수정 가능성을 원천 차단했습니다.
- 반대로 `Auto` 모드와 계획 승인 이후(`plan_approved=True`)에는 일반 검증 명령(`pytest`, `ruff`, `npm test` 등)의 불필요한 승인 창을 없애고, `rm`·`git push`·`git reset --hard` 같은 파괴적 명령만 선별해 멈추게(`ShellGuard`) 하여 개발 흐름과 안전성을 함께 확보했습니다.

---

## 2. 도구를 늘리기보다 점진적 노출(`SKILL.md`)과 서브에이전트 격리를 써야 합니다

기능마다 전용 도구를 계속 추가하면 매 턴 읽어야 하는 스키마 토큰이 불어나고 모델의 도구 선택 정확도가 떨어집니다.

- 코어 도구는 9개(`ls`, `read_file`, `write_file`, `edit_file`, `glob`, `grep`, `execute`, `ask_user`, `task`)로 얇게 유지하고, 온보딩·검증(`verify`)·외부 `skills.sh` 패키지는 필요할 때만 읽어 들이는 **`SKILL.md` 점진적 노출**로 풀었습니다.
- 많은 파일을 뒤지는 탐색과 변경 코드 리뷰는 메인 문맥과 분리된 **읽기 전용 서브에이전트(`Explorer`, `Code Reviewer`)**의 독립 `sub_messages` 루프에서 처리해, 부모 문맥 오염과 '자기 코드 호의적 평가 편향'을 함께 해결했습니다.

---

## 3. 인간 개입(HITL)은 평문 질문이 아니라 상태가 보존되는 인터럽트여야 합니다

애매한 요구사항을 채팅 평문으로 여러 개 물어보면 대화 흐름이 쉽게 깨집니다.

- LangGraph의 `interrupt()` / `Command(resume=...)`로 그래프 실행 지점을 SQLite에 얼려 두고 선택지 질문(`ask_user`)이나 계획·위험 명령 승인을 받은 뒤 멈췄던 줄부터 이어 달리도록 구현했습니다.
- 이때 일반 도구 실행 에러는 `ToolMessage`로 감싸 모델이 스스로 고치게 하되, `interrupt()`와 스트림 취소(`CancelledError`) 신호는 절대 삼키지 않고 상위로 전파해야 상태 머신이 깨지지 않습니다.

---

## 4. 자율 검증에는 중단 기준과 '심판 파일 보호'가 필요합니다

- **Three-Strike 규칙**: 검증 명령이 연속 3회 실패하면 무분별한 재시도를 멈추고 실패 증거를 정리해 보고하도록 제어했으며, 검증 통과 후 파일을 다시 고치면 기존 통과 스탬프를 즉시 무효화했습니다.
- **검증 기준 보호 (*"Changes can't modify their own checks"*)**: `AGENTS.md`, `.github/workflows/*`, 아키텍처 경계 테스트 파일을 에이전트가 임의로 고쳐 통과시키지 못하도록 자율 모드에서도 반드시 사용자 승인을 거치게 막았습니다.

---

## 5. 코딩 에이전트의 Revert는 '파일 + DB + LLM 기억' 3계층을 함께 되감아야 합니다

- 미커밋 상태의 멀티턴 작업에서 특정 턴만 되돌리기 위해 SHA-256 콘텐츠 주소화 스냅샷(`TurnCheckpointStore`)을 사용했으며, 클라이언트 중단(`Stop`) 시에도 직전까지의 변경 매니페스트를 회수하도록 보강했습니다.
- 디스크 파일만 되돌리면 체크포인터에 남은 옛 기억 때문에 모델이 환각을 일으키므로, **① 파일 스냅샷 복원 → ② SQLite 메시지 절삭 → ③ LangGraph 스레드 초기화 및 이전 대화 재주입(`prior_messages`)** 세 계층을 함께 맞춰야 완전한 되돌리기가 성립합니다.

---

## 6. 아키텍처 경계는 문서가 아니라 AST 테스트로 지켜야 합니다

- 제품 이름(`APP_NAME`)은 표시 상수로만 분리하고 내부 경로(`.data/sessions.db`)와 환경변수(`DATA_DIR`, `SQLITE_JOURNAL_MODE`, `LOG_LEVEL`)는 역할 기반 이름으로 유지해 변경 파급을 줄였습니다.
- 4개 도메인(`sessions`, `agent`, `artifacts`, `skills`) 사이의 참조 금지 규칙을 파이썬 `ast` 정적 검사(`test_architecture_boundaries.py`)로 자동화한 덕분에 기능을 거듭 확장하는 동안에도 도메인 결합도가 무너지지 않았습니다.
